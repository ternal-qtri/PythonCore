Môi Trường Ảo, Quản Lý Gói & Cấu Trúc Dự Án

Trước khi viết dòng code Django đầu tiên, lập trình viên bắt buộc phải nắm vững kỹ năng cô lập môi trường phụ thuộc (dependencies). Không bao giờ cài đặt Django trực tiếp vào Python của hệ điều hành.

Mức độ: Bắt buộc (Foundation) Thực thi: CLI & Module Thời gian đọc: 12 phút
#

1. Môi Trường Ảo (Virtual Environment - venv)

Môi trường ảo tạo ra một thư mục độc lập chứa phiên bản Python riêng và bộ thư viện tách biệt hoàn toàn với hệ thống và các dự án khác trên cùng máy tính.

python -m venv <env_name> Core Command
Cú pháp khởi tạo và kích hoạt môi trường ảo trên Linux/macOS và Windows.
💻 Terminal Commands (Bash / PowerShell) 
# 1. Khởi tạo môi trường ảo tên 'venv'
python3 -m venv venv

# 2. Kích hoạt môi trường trên Linux / macOS:
source venv/bin/activate

# Hoặc kích hoạt trên Windows (PowerShell):
# .\venv\Scripts\Activate.ps1

# 3. Kiểm tra đường dẫn python đang chạy
which python

# 4. Khi muốn thoát môi trường ảo:
deactivate
Terminal Output Đối Chiếu active console 
$ python3 -m venv venv
$ source venv/bin/activate
(venv) $ which python
/home/user/my_django_project/venv/bin/python

(venv) $ deactivate
$ which python
/usr/bin/python3
🎯

Ứng dụng trực tiếp trong Django:

Mỗi dự án Django thường sử dụng phiên bản Django khác nhau (ví dụ: Dự án cũ dùng Django 3.2 LTS, dự án mới dùng Django 5.1). Nếu không có venv, việc cài đặt sẽ đè lên nhau và gây lỗi crash toàn bộ hệ thống.

⚠️

Cạm bẫy cần tránh:

Tuyệt đối KHÔNG commit thư mục venv/ lên Git. Luôn thêm venv/ và .env vào tệp .gitignore!

#

2. Quản Lý Gói: pip & requirements.txt

Cách đóng gói toàn bộ danh sách thư viện và cài đặt hàng loạt trên server production.

pip install, freeze & requirements.txt Django Workflow
Cài đặt Django, xuất tệp cấu hình phụ thuộc và tái thiết lập môi trường bằng 1 dòng lệnh.
💻 Terminal Commands 
# Cài đặt Django và các package liên quan
pip install django psycopg2-binary pillow

# Xuất danh sách thư viện đã cài ra file
pip freeze > requirements.txt

# Xem nội dung file requirements.txt vừa tạo
cat requirements.txt

# Trên Server / Thành viên khác trong team clone về chỉ cần:
pip install -r requirements.txt
Terminal Output Đối Chiếu stdout 
(venv) $ pip freeze > requirements.txt
(venv) $ cat requirements.txt
asgiref==3.8.1
Django==5.1.2
Pillow==10.4.0
psycopg2-binary==2.9.9
sqlparse==0.5.1

(venv) $ pip install -r requirements.txt
Requirement already satisfied: asgiref==3.8.1 ...
Requirement already satisfied: Django==5.1.2 ...
🎯

Ứng dụng trực tiếp trong Django:

Tệp requirements.txt là tài liệu bắt buộc khi deploy Django lên Docker, AWS, Render, Heroku hay VPS. Nó đảm bảo server chạy chính xác 100% các phiên bản thư viện đã phát triển ở môi trường local.

3. sys.path & Cơ Chế Tìm Kiếm Module của Python

Hiểu rõ sys.path là chìa khóa để trả lời câu hỏi: "Tại sao Django import được các app mà không báo lỗi ModuleNotFoundError?"

import sys; sys.path Core Python
sys.path là một danh sách (list) các chuỗi đường dẫn thư mục mà Python sẽ lần lượt duyệt qua khi bạn gõ lệnh import ....
💻 inspect_path.py 
import sys
from pathlib import Path

print("Tổng số đường dẫn tìm kiếm:", len(sys.path))
print("Thư mục hiện tại (luôn ở vị trí đầu tiên index 0):")
print(" ->", sys.path[0])

# Mô phỏng cách manage.py của Django thêm root vào sys.path
CURRENT_DIR = Path(__file__).resolve().parent
if str(CURRENT_DIR) not in sys.path:
    sys.path.insert(0, str(CURRENT_DIR))

print("Đã nạp đường dẫn gốc thành công!")
Terminal Output Đối Chiếu stdout 
$ python inspect_path.py
Tổng số đường dẫn tìm kiếm: 6
Thư mục hiện tại (luôn ở vị trí đầu tiên index 0):
 -> /home/user/my_django_project
Đã nạp đường dẫn gốc thành công!
🎯

Ứng dụng trực tiếp trong Django:

Khi bạn chạy lệnh python manage.py runserver, file manage.py tự động biến thư mục gốc dự án thành điểm xuất phát của sys.path. Nhờ đó, ở bất kỳ file nào bạn cũng có thể gõ from blog.models import Post hoặc from users.views import LoginView mà không sợ lỗi đường dẫn.

4. Cấu Trúc Dự Án Django Chuẩn

Cách tổ chức thư mục khi kết hợp Python Virtualenv và Django Project.

Django Directory Anatomy Architecture
📂 Sơ đồ cây thư mục (File Tree) 
my_project/                 # Thư mục gốc dự án
│
├── venv/                   # Môi trường ảo (KHÔNG commit vào git)
├── .gitignore              # Khai báo bỏ qua venv, .env, *.pyc
├── requirements.txt        # Danh sách package
├── manage.py               # CLI entrypoint của Django
│
├── core_config/            # Thư mục cấu hình tổng (Project Settings)
│   ├── __init__.py         # Đánh dấu đây là Python Package
│   ├── settings.py         # Cấu hình CSDL, INSTALLED_APPS, Middleware
│   ├── urls.py             # Định tuyến URL cấp cao nhất
│   ├── asgi.py             # Cổng chạy Async server
│   └── wsgi.py             # Cổng chạy Sync WSGI server (Gunicorn)
│
└── blog_app/               # Một ứng dụng con (Django App)
    ├── __init__.py
    ├── models.py           # Định nghĩa CSDL (OOP Classes)
    ├── views.py            # Xử lý logic và request
    ├── urls.py             # Route riêng của app
    ├── forms.py            # Xử lý biểu mẫu dữ liệu
    └── admin.py            # Đăng ký hiển thị lên Django Admin
Vai trò cụ thể trong Python Runtime 
✔ manage.py:
  Script dùng để chạy server, migrate database,
  tạo superuser.

✔ settings.py:
  Thực chất là 1 module Python chuẩn, biến cấu hình
  đều là biến Python dạng SCREAMING_SNAKE_CASE.

✔ __init__.py:
  Báo cho Python trình thông dịch biết thư mục
  này là một Python Package hợp lệ.
