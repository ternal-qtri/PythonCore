Dunder Methods, Thuộc Tính Ảo & Mixins Trong Django

Khai phá các cơ chế nội tại tinh vi nhất của Python OOP: từ phương thức ma thuật __str__ giúp Django Admin hiển thị tên bản ghi rõ ràng, thuộc tính @property để tính toán dữ liệu động, đến cơ chế Mixins & MRO vận hành các Class-Based Views (CBV).

1. Magic Method __str__ & Hiển Thị Trên Django Admin

Khi bạn in một đối tượng hoặc hiển thị trong bảng quản trị Django Admin, nếu không có hàm __str__, bạn sẽ chỉ thấy dòng chữ vô nghĩa dạng: <Post object (1)>.

def __str__(self) -> str Mandatory on Models
Hàm ma thuật quy định chuỗi văn bản đại diện cho đối tượng khi được gọi bởi str(obj), print(obj) hoặc hiển thị trên giao diện người dùng.
💻 dunder_str_demo.py 
# Trường hợp 1: Không định nghĩa __str__
class BadArticleModel:
    def __init__(self, id, title):
        self.id = id
        self.title = title

# Trường hợp 2: Có định nghĩa __str__ chuẩn Django
class GoodArticleModel:
    def __init__(self, id, title, author):
        self.id = id
        self.title = title
        self.author = author

    def __str__(self):
        return f"[{self.id}] {self.title} (Tác giả: {self.author})"

bad_item = BadArticleModel(1, "Bản ghi lỗi hiển thị")
good_item = GoodArticleModel(101, "Kiến Trúc Django Chuẩn", "qtri")

print("Khi không có __str__:", bad_item)
print("Khi có __str__ chuẩn:", good_item)
Terminal Output Đối Chiếu stdout 
$ python dunder_str_demo.py
Khi không có __str__: <__main__.BadArticleModel object at 0x7f9a12c4>
Khi có __str__ chuẩn: [101] Kiến Trúc Django Chuẩn (Tác giả: qtri)
🎯

Ứng dụng trực tiếp trong Django:

Trong Django Admin, danh sách chọn bài viết, tag, hoặc danh mục sản phẩm (Foreign Key dropdown) sẽ gọi trực tiếp phương thức __str__ của Model để hiển thị nhãn cho người dùng bấm chọn. Mọi Model bạn viết trong Django đều nên có hàm __str__!

2. @property: Tạo Thuộc Tính Tính Toán (Computed Field)

Không cần tạo thêm cột trong database gây lãng phí dung lượng. @property cho phép biến một hàm thành một thuộc tính chỉ đọc (getter), gọi không cần dấu ngoặc tròn ().

@property Virtual Attributes
💻 property_model.py 
class UserAccount:
    def __init__(self, first_name, last_name, points):
        self.first_name = first_name
        self.last_name = last_name
        self.points = points

    @property
    def full_name(self):
        """Tự động ghép họ và tên đầy đủ"""
        return f"{self.first_name} {self.last_name}"

    @property
    def is_vip(self):
        """Kiểm tra điều kiện tài khoản VIP"""
        return self.points >= 1000

user = UserAccount("Nguyễn", "Quốc Trị", 1500)

# Truy cập như thuộc tính bình thường (không có ngoặc đơn ())!
print("Họ và tên:", user.full_name)
print("Tài khoản VIP?", user.is_vip)
Terminal Output Đối Chiếu stdout 
$ python property_model.py
Họ và tên: Nguyễn Quốc Trị
Tài khoản VIP? True
🎯

Ứng dụng trực tiếp trong Django:

Trong Django Templates, bạn không thể gọi hàm kèm tham số hay ngoặc tròn. Nhưng nhờ có @property, trong file HTML bạn có thể viết trực tiếp: <h1>{{ user.full_name }}</h1> và {% if user.is_vip %} Huy hiệu VIP {% endif %}.

3. @classmethod & @staticmethod

Phân biệt các loại phương thức trong Python và cách Django dùng chúng để tạo Model Managers và Helper functions.

@classmethod vs @staticmethod Method Types
💻 class_static_demo.py 
class Order:
    TAX_RATE = 0.08

    def __init__(self, order_id, subtotal):
        self.order_id = order_id
        self.subtotal = subtotal

    # 1. Instance Method: có self
    def calculate_total(self):
        return self.subtotal * (1 + Order.TAX_RATE)

    # 2. Class Method: có cls, thường làm Factory khởi tạo
    @classmethod
    def from_raw_payload(cls, payload):
        return cls(order_id=payload["id"], subtotal=payload["amount"])

    # 3. Static Method: độc lập, không self không cls
    @staticmethod
    def format_currency(amount):
        return f"{amount:,.0f} đ"

# Dùng classmethod tạo instance từ dict:
raw_data = {"id": "ORD-999", "amount": 500000}
ord_obj = Order.from_raw_payload(raw_data)

print("Mã đơn hàng:", ord_obj.order_id)
print("Tổng tiền đã gồm thuế:", Order.format_currency(ord_obj.calculate_total()))
Terminal Output Đối Chiếu stdout 
$ python class_static_demo.py

Tổng tiền đã gồm thuế: 540,000 đ

4. Đa Kế Thừa & Thứ Tự Phân Giải MRO (Method Resolution Order)

Python cho phép một lớp kế thừa từ nhiều lớp cha cùng lúc. Thuật toán C3 Linearization quyết định thứ tự Python tìm kiếm hàm: từ trái sang phải trong danh sách kế thừa.

ClassName.__mro__ MRO Inspector
💻 mro_inspection.py 
class BaseView:
    def dispatch(self):
        print("1. BaseView.dispatch: Xử lý request cơ bản")

class AuthMixin:
    def dispatch(self):
        print("🔒 AuthMixin.dispatch: Kiểm tra đăng nhập trước!")
        super().dispatch()

# Thứ tự đúng: Mixin ở trước, BaseView ở sau
class SecureDashboardView(AuthMixin, BaseView):
    pass

view_obj = SecureDashboardView()
view_obj.dispatch()

print("\nThứ tự duyệt MRO:")
for idx, cls in enumerate(SecureDashboardView.__mro__):
    print(f" [{idx}] {cls.__name__}")

$ python mro_inspection.py

5. Mixins Trong Django Class-Based Views (CBV)

Trong Django, Mixin là một lớp nhỏ độc lập cung cấp thêm chức năng (như xác thực, phân quyền, lọc theo user).

class MyView(LoginRequiredMixin, ListView) CBV Rule
