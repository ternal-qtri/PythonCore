Lập Trình Hướng Đối Tượng: Nền Tảng Của Django ORM

Django được mệnh danh là framework tôn sùng OOP. Toàn bộ bảng cơ sở dữ liệu (ORM Models), biểu mẫu nhập liệu (Forms), và màn hình hiển thị (Class-Based Views) đều là các lớp Python kế thừa lẫn nhau.

1. Class, Instance & Bản Chất Của Từ Khóa self

Class là bản thiết kế (blueprint), còn Instance là đối tượng thực tế sinh ra từ bản thiết kế đó. Từ khóa self đại diện cho chính thực thể (instance) cụ thể đang gọi hàm.

class MyModel; def method(self) OOP Syntax
Khi bạn gọi obj.method(), thực chất Python sẽ biên dịch ngầm thành MyClass.method(obj). Vì vậy tham số đầu tiên của mọi method luôn là self.
💻 oop_basics.py 
class UserProfile:
    def __init__(self, username, email):
        # Gán dữ liệu vào chính instance này thông qua self
        self.username = username
        self.email = email
        self.is_active = True

    def deactivate(self):
        self.is_active = False
        print(f"Tài khoản '{self.username}' đã bị khóa!")

# Khởi tạo 2 đối tượng độc lập:
user1 = UserProfile("alice", "alice@example.com")
user2 = UserProfile("bob", "bob@example.com")

user1.deactivate()

print("Trạng thái user1 (Alice):", user1.is_active)
print("Trạng thái user2 (Bob):", user2.is_active)
Terminal Output Đối Chiếu stdout 
$ python oop_basics.py
Tài khoản 'alice' đã bị khóa!
Trạng thái user1 (Alice): False
Trạng thái user2 (Bob): True
🎯

Ứng dụng trực tiếp trong Django:

Mỗi hàng trong bảng CSDL (Database Record) khi được truy vấn bằng post = Post.objects.get(id=1) sẽ được Django đóng gói thành một instance của class Post. Bạn có thể truy cập các cột của bảng đó thông qua post.title, post.created_at.

2. Tính Kế Thừa (Inheritance) Trong Django Framework

Django cung cấp sẵn các lớp cơ sở mạnh mẽ như models.Model, forms.ModelForm, views.generic.ListView. Bạn chỉ cần kế thừa lại và chỉ định cấu hình riêng của mình.

class ChildClass(ParentClass) Django Models & Forms
💻 model_inheritance_concept.py 
# Giả lập class cơ sở Model của Django
class BaseDjangoModel:
    def __init__(self, **kwargs):
        for key, value in kwargs.items():
            setattr(self, key, value)

    def save(self):
        print(f"💾 [SQL INSERT/UPDATE] Lưu bản ghi vào bảng '{self.__class__.__name__.lower()}'")

# Lập trình viên định nghĩa Model bằng kế thừa:
class Product(BaseDjangoModel):
    def calculate_tax(self):
        return self.price * 0.1

prod = Product(name="Bàn phím cơ", price=1500000)
print("Sản phẩm:", prod.name)
print("Thuế VAT 10%:", prod.calculate_tax(), "VNĐ")
prod.save() # Gọi hàm kế thừa từ BaseDjangoModel

$ python model_inheritance_concept.py

Thuế VAT 10%: 150000.0 VNĐ
💾 [SQL INSERT/UPDATE] Lưu bản ghi vào bảng 'product'

3. Ghi Đè Phương Thức (Override) & Hàm super()

Khi phương thức của lớp cha chưa đáp ứng đủ yêu cầu, lớp con có quyền viết lại hàm cùng tên và dùng super().method() để tận dụng logic của lớp cha mà không làm hỏng tính năng gốc.

super().save(*args, **kwargs) Must-Know Technique
Kỹ thuật ghi đè hàm save() được sử dụng phổ biến nhất trong Django để tự động tính toán dữ liệu (như tạo slug, mã hóa thẻ, hash password) ngay trước khi dữ liệu được ghi xuống Database.
💻 override_save_slug.py 
class BaseModel:
    def save(self, *args, **kwargs):
        print("-> [Database Engine] Đã ghi dữ liệu thành công!")

class Article(BaseModel):
    def __init__(self, title):
        self.title = title
        self.slug = ""

    def save(self, *args, **kwargs):
        # Bước 1: Can thiệp dữ liệu trước khi lưu
        if not self.slug:
            self.slug = self.title.lower().replace(" ", "-")
            print(f"-> [Pre-Save Hook] Tạo slug: '{self.slug}'")

        # Bước 2: BẮT BUỘC gọi super().save()
        super().save(*args, **kwargs)

art = Article("Huong Dan Hoc Django 2026")
art.save()
print("Slug kết quả:", art.slug)
Terminal Output Đối Chiếu stdout 
$ python override_save_slug.py
-> [Pre-Save Hook] Tạo slug: 'huong-dan-hoc-django-2026'
-> [Database Engine] Đã ghi dữ liệu thành công!
Slug kết quả: huong-dan-hoc-django-2026
⚠️

Quên gọi super().save():

Nếu bạn ghi đè hàm save() mà quên dòng lệnh super().save(*args, **kwargs), dữ liệu của bạn sẽ chỉ thay đổi trong bộ nhớ RAM và HOÀN TOÀN KHÔNG ĐƯỢC LƯU VÀO DATABASE!

4. Phân Biệt Class Attribute vs Instance Attribute

Tại sao trong Django Model bạn lại viết title = models.CharField(...) ở ngoài thân class chứ không viết trong def __init__?

Class Attributes vs Instance Attributes Mental Model
💻 class_vs_instance_attr.py 
class DjangoModelDemo:
    # 1. CLASS ATTRIBUTE: Chia sẻ cho toàn bộ class
    # Trong Django, đây chính là cách định nghĩa các cột Database (ORM Fields)!
    table_name = "tbl_articles"
    default_status = "draft"

    def __init__(self, title):
        # 2. INSTANCE ATTRIBUTE: Dữ liệu riêng biệt của từng bản ghi
        self.title = title

# Truy cập trực tiếp qua tên Class mà không cần tạo đối tượng:
print("Tên bảng CSDL khai báo ở Class:", DjangoModelDemo.table_name)

item1 = DjangoModelDemo("Bài viết 1")
item2 = DjangoModelDemo("Bài viết 2")

print("Title bản ghi 1:", item1.title)
print("Title bản ghi 2:", item2.title)
print("Cả 2 đều chia sẻ status:", item1.default_status, "|", item2.default_status)

$ python class_vs_instance_attr.py
Tên bảng CSDL khai báo ở Class: tbl_articles
Title bản ghi 1: Bài viết 1
Title bản ghi 2: Bài viết 2
Cả 2 đều chia sẻ status: draft | draft
🎯

Bản chất của Django ORM:

Django sử dụng một kỹ thuật Python nâng cao gọi là Metaclass để quét toàn bộ Class Attributes (ví dụ: title = models.CharField(...), price = models.DecimalField(...)) và tự động sinh ra mã SQL CREATE TABLE ... tương ứng trong lệnh python manage.py makemigrations.
