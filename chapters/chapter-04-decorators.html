Decorators: Bản Chất, Kỹ Thuật & Ứng Dụng Trong Django

Decorator cho phép mở rộng hoặc biến đổi hành vi của một hàm mà không cần sửa đổi mã nguồn gốc của hàm đó. Trong Django, bảo mật đăng nhập, kiểm tra CSRF token, hay giới hạn phương thức HTTP đều được thực hiện qua các Decorator đặt trước các view.

#

1. Bản Chất Của Ký Tự @: Hàm Bọc Hàm (Wrapper)

Cú pháp @my_decorator thực chất chỉ là "đường cú pháp" (syntactic sugar) tương đương với biểu thức gán: target_func = my_decorator(target_func).

@decorator_name Core Pattern
Một hàm nhận hàm đích làm tham số, trả về một hàm bọc (wrapper) thực thi các tác vụ trước và sau khi hàm gốc chạy.
💻 basic_decorator.py 
def log_execution(func):
    def wrapper(*args, **kwargs):
        print(f"🚀 [START] Đang chuẩn bị gọi hàm '{func.__name__}'...")
        result = func(*args, **kwargs)
        print(f"🏁 [DONE] Kết thúc hàm '{func.__name__}'!")
        return result
    return wrapper

# Áp dụng decorator bằng ký hiệu @
@log_execution
def render_dashboard(username):
    print(f"   -> Đang tải trang quản trị cho tài khoản: {username}")
    return "HTML Content Rendered"

# Gọi hàm bình thường:
output = render_dashboard("admin_qtri")
print("Kết quả trả về:", output)

Ứng dụng trực tiếp trong Django:

Trước khi nội dung hàm view của bạn được chạy, Django dùng Decorator để: kiểm tra xem user đã đăng nhập chưa, tính toán thời gian phản hồi (response time), hoặc xác minh CSRF token.

2. Tại Sao Bắt Buộc Phải Dùng functools.wraps?

Khi bọc hàm bằng wrapper, nếu không có @functools.wraps(func), tên hàm gốc __name__ và tài liệu docstring __doc__ sẽ bị ghi đè thành wrapper! Điều này gây lỗi nghiêm trọng cho bộ định tuyến URL của Django.

from functools import wraps Metadata Preservation
💻 wraps_comparison.py 
from functools import wraps

# ❌ Decorator KHÔNG dùng wraps (Nguy hiểm!)
def bad_decorator(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

# ✅ Decorator CHUẨN dùng @wraps
def good_decorator(func):
    @wraps(func)  # Sao chép metadata của func gốc sang wrapper
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@bad_decorator
def view_profile():
    """Hàm hiển thị trang cá nhân"""
    pass

@good_decorator
def view_settings():
    """Hàm hiển thị trang cài đặt"""
    pass

print("Tên hàm view_profile:", view_profile.__name__)
print("Tên hàm view_settings:", view_settings.__name__)
print("Docstring view_settings:", view_settings.__doc__)

Hậu quả trong Django nếu thiếu wraps:

Hàm reverse('view_name') trong django.urls hoặc các công cụ tự động sinh tài liệu Swagger/OpenAPI sẽ không thể nhận diện được tên thật của view, dẫn đến việc reverse URL thất bại hoàn toàn.

3. Tự Tạo Decorator Nhận Tham Số (3 Lớp Lồng Nhau)

Khi bạn muốn truyền tham số cấu hình vào decorator (ví dụ danh sách quyền cho phép: @roles_allowed(["admin", "manager"])), chúng ta cần một hàm bao ngoài cùng nhận tham số đó rồi trả về decorator.

def decorator_factory(*config_args) Custom Auth Decorator
💻 custom_role_decorator.py 
from functools import wraps

# Tầng 1: Hàm nhận tham số cấu hình
def roles_allowed(allowed_roles_list):
    # Tầng 2: Decorator nhận hàm đích func
    def decorator(func):
        @wraps(func)
        # Tầng 3: Wrapper thực thi khi hàm được gọi
        def wrapper(request, *args, **kwargs):
            user_role = request.get("role")
            if user_role not in allowed_roles_list:
                print(f"⛔ 403 Forbidden: Role '{user_role}' không có quyền truy cập!")
                return "HTTP 403 Forbidden"
            
            print(f"✅ Quyền hợp lệ ({user_role}), cho phép tiếp tục...")
            return func(request, *args, **kwargs)
        return wrapper
    return decorator

# Áp dụng vào view:
@roles_allowed(["admin", "superadmin"])
def delete_database_view(request):
    return "Đã dọn sạch database!"

user_guest = {"name": "Tom", "role": "guest"}
user_admin = {"name": "Sarah", "role": "admin"}

print("--- Thử nghiệm 1 (Guest) ---")
delete_database_view(user_guest)

print("\n--- Thử nghiệm 2 (Admin) ---")
res = delete_database_view(user_admin)
print("Kết quả:", res)

4. Các Decorators Cốt Lõi Tích Hợp Sẵn Trong Django

Khi làm việc với Django views thực tế, bạn sẽ dùng các decorator này mỗi ngày:

Decorator Module Import Ý nghĩa & Hành vi
@login_required django.contrib.auth.decorators Chặn người dùng chưa đăng nhập, tự động redirect sang trang /login/?next=...
@permission_required('app.perm') django.contrib.auth.decorators Kiểm tra xem tài khoản có mã quyền hạn cụ thể hay không
@require_http_methods(["GET", "POST"]) django.views.decorators.http Chỉ cho phép các phương thức HTTP chỉ định; phương thức khác trả về HttpResponseNotAllowed (405)
@require_POST django.views.decorators.http Chỉ cho phép duy nhất phương thức POST (rất tiện cho view xử lý nút Delete hoặc Like)
@csrf_exempt django.views.decorators.csrf Bỏ qua kiểm tra CSRF token cho view (thường dùng cho Webhook từ bên thứ 3 như Stripe/VNPAY)
