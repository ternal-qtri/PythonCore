Modules, Packages & Kiến Trúc Dự Án Django

Một dự án Django lớn được chia thành nhiều ứng dụng con (apps). Nắm vững cách Python quản lý namespace, nhập xuất module (imports), và đặc biệt là cách xử lý lỗi import vòng (Circular Import) trong Models và Signals.

Mức độ: Thiết yếu (Essential) Chủ đề: Namespace & Code Organization Thời gian đọc: 14 phút
#

1. Phân Biệt Module vs Package & Vai Trò Của __init__.py

Module là một tệp Python đơn lẻ có đuôi .py. Package là một thư mục chứa tệp đặc biệt __init__.py.

__init__.py Package Marker
Khi Python thấy thư mục có __init__.py, nó sẽ xem toàn bộ thư mục đó là một Package hợp lệ và cho phép các file bên ngoài dùng cú pháp dấu chấm . để import vào bên trong.
📂 Cấu trúc thư mục App trong Django 
my_django_project/
├── manage.py
├── core_settings/
│   ├── __init__.py           # Đánh dấu core_settings là 1 package
│   ├── settings.py
│   └── urls.py
└── blog/                     # Django App "blog"
    ├── __init__.py           # Đánh dấu blog là 1 package
    ├── models.py
    └── views.py
Cú pháp import tương ứng 
# Nhờ có __init__.py, bạn có thể viết:
from core_settings import settings
from blog.models import Post
from blog.views import PostListView

✔ Cú pháp dấu chấm '.' phản ánh chính xác
  cấu trúc thư mục của Package trên ổ cứng.
#

2. Absolute Imports vs Relative Imports

Hiểu khi nào nên dùng from .models import Post (Relative) và khi nào dùng from blog.models import Post (Absolute).

from . import models vs from app import models Import Rules
💻 blog/views.py 
# 1. RELATIVE IMPORT (1 dấu chấm '.' là cùng thư mục hiện tại):
from .models import Post, Comment
from .forms import CommentForm

# 2 dấu chấm '..' là lùi lên 1 cấp thư mục cha:
from ..shared_utils.helpers import slugify_vietnamese

# 2. ABSOLUTE IMPORT (Đi từ thư mục gốc của dự án):
from django.shortcuts import render, get_object_or_404
from users.models import UserProfile

def post_detail(request, slug):
    post = get_object_or_404(Post, slug=slug)
    return render(request, "blog/detail.html", {"post": post})
Quy ước chuẩn PEP 8 & Django 
✔ Trong nội bộ 1 Django App:
  Dùng relative from .models import ...
  Ưu điểm: Nếu sau này bạn đổi tên app 'blog'
  thành 'articles', toàn bộ code bên trong
  views.py vẫn hoạt động bình thường!

✔ Khi gọi chéo giữa các Django Apps khác nhau:
  Bắt buộc dùng absolute: from users.models ...

3. Cơn Ác Mộng Circular Import & 3 Cách Giải Quyết

Xảy ra khi Module A cố gắng import Module B, nhưng trong khi đó Module B lại đang cố gắng import ngược lại Module A!

Circular Import Solutions Critical Fix
💡

3 Cách Giải Quyết Triệt Để Trong Django:

1. Dùng String Reference cho ForeignKey:
Thay vì author = models.ForeignKey(User, ...) (yêu cầu phải import class User), hãy dùng chuỗi chuỗi tên Model: author = models.ForeignKey('auth.User', ...) hoặc 'users.UserProfile'. Django sẽ tự động trì hoãn liên kết cho đến khi cả 2 model đã được tải xong!

2. Local / Lazy Import bên trong hàm:
Đặt lệnh import ... bên trong thân của hàm hoặc phương thức cụ thể thay vì đặt ở đầu file.

3. Đăng ký Signals trong AppConfig.ready():
Trong apps.py: 

class BlogConfig(AppConfig):
    name = 'blog'
    def ready(self):
        import blog.signals  # Chỉ nạp signals sau khi toàn bộ ORM Models đã sẵn sàng!

#

4. Giải Mã __name__ == '__main__' Trong manage.py

Tại sao trong file manage.py luôn có câu lệnh if __name__ == '__main__':?

if __name__ == '__main__' Entrypoint Guard
💻 manage.py (Giải mã mã nguồn Django) 
import os
import sys

def main():
    # Thiết lập biến môi trường trỏ tới file settings của dự án
    os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
    try:
        from django.core.management import execute_from_command_line
    except ImportError as exc:
        raise ImportError("Không tìm thấy Django. Bạn đã activate venv chưa?") from exc
    
    # Chạy các lệnh như runserver, makemigrations
    execute_from_command_line(sys.argv)

# Khối lệnh này chỉ chạy khi file được gõ trực tiếp qua terminal:
# $ python manage.py runserver
# Nếu file này bị import từ nơi khác, khối này sẽ KHÔNG chạy!
if __name__ == '__main__':
    main()
Quy luật biến __name__ của Python 
✔ Khi chạy trực tiếp:
  $ python manage.py
  -> Python tự động gán: __name__ = "__main__"
  -> Điều kiện True: Lệnh main() kích hoạt!

✔ Khi bị import từ file khác:
  import manage
  -> Python gán: __name__ = "manage"
  -> Điều kiện False: Không chạy gì cả (An toàn!)
